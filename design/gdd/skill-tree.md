## Overview

**技能树系统**是《废土喵影》的Build深度引擎，统一负责猫武士所有技能的解锁与升级。每种武器（猫爪、长尾刃、鱼骨大剑、电磁铃铛）拥有独立的技能分支，玩家通过消耗技能点逐步解锁新招式、强化已有技能、甚至改变武器特性——例如让猫爪的闪避反击附带减速，或让鱼骨大剑的蓄力攻击附加范围冲击波。技能树同时是玩家能力升级的载体——冲刺距离、弹反窗口等通用能力也可通过技能树分支强化。

**玩家直接感受它**：在据点的技能树界面（或猫族导师NPC处），玩家看到一张按武器分支组织的技能图谱。每次选择都是一次Build决策——"我要深化反击路线，还是拓宽连招终结？"每个解锁的技能都在下次战斗中立刻有可感知的变化——新招式、新效果、新组合。技能选择让玩家打出属于自己的战斗风格。

**数据层职责**：技能树通过 DataManager 加载 `skill_tree.json` 配置，向猫科战斗系统注册 modifier provider——战斗系统通过统一接口查询当前已解锁技能的加成（攻击力修正、冷却修正、窗口修正等），而非硬编码绑定。技能解锁状态持久化到存档系统。

**为什么存在**：没有技能树，4种武器的差异化只停留在基础参数层面——玩家无法构建"我的猫爪是反击特化"这种个人化Build。技能树把"技巧优先"从操作层延伸到Build层：玩家不仅通过操作表达技巧，还通过技能选择表达策略。

## Player Fantasy

**「磨爪石」+「铸爪成道」— 每一点技能点，都是爪子变锋利的声音**

技能树的终极使命是让玩家的猫武士成为**独一无二的猎手**——不是通过数值碾压，而是通过**磨砺手段的层次**。每次投入技能点都像猫在磨爪石上留下爪痕：清脆、有节奏、每一下都让爪子更锋利。解锁之后立刻去战斗验证——"我的反击现在带减速了"——下一场战斗里，操作多了一层，策略多了一种。玩家感受到的不是"我数值变大了"，而是**"我变强了，因为我会的更多了"**。

**锚定时刻（精通层）**：Boss战结束后回到据点，打开技能树。你在猫爪分支看到「闪避反击附带减速」——这正是打Boss时想要的效果。投入技能点，UI传来利爪划过磨石的清脆音效，节点亮起金色爪痕。下一场战斗，闪避、反击、敌人减速——你的爪子确实更锋利了。不是数字变大了，是你**多了一层手段**。

**锚定时刻（实验层）**：打开技能树，四条武器分支从中心向四个方向铺展。你顺着猫爪分支看下去，发现深处有一个节点写着「连招终结击飞」——如果解锁它，你的连招链会完全改变。你不知道该往哪走，但你**想看看每条路尽头是什么**。

**锚定时刻（表达层）**：游戏中期，回头看自己的技能树——猫爪分支深亮，反击路线已打通；长尾刃只点亮了基础横扫；鱼骨大剑完全空白。你的Build是「反击特化猫爪使」，别人走的是「蓄力鱼骨一刀流」。面对同一个Boss，打法完全不同。你的技能选择是你在这废土上留下的**爪印**——独一无二的战斗签名。

**核心承诺**：
- **磨砺有痕迹**：每个技能点都让猫武士多一层战斗手段——你打磨的不是数值，是你使用武器的方式
- **猎径有分叉**：技能树的每条分支都是一种狩猎策略的纵深——你的选择决定了你如何猎杀这个世界的猎物
- **爪印有个性**：技能树让你的猫武士成为独一无二的猎手——同样的武器，不同的道路，打出只属于你的战斗

**语言规则**：
- 界面/操作层用磨砺语言（磨爪、爪痕、锋利）
- Build差异层用印记语言（爪印、我的路、我的打法）
- 探索/实验层用猎径语言（分叉、深处、尽头）
- 禁止出现"升级""强化""点数"等RPG数值词汇在幻想层

## Detailed Design

### Core Rules

#### 规则1：技能树结构

技能树采用**中心辐射布局**——中央为通用区域（能力升级），四条武器分支向四个方向延伸。

```
                    ┌─────────────┐
                    │  猫爪分支    │
                    │ (反击流·上)  │
                    └──────┬──────┘
                           │
  ┌──────────┐     ┌───────┴───────┐     ┌──────────┐
  │ 长尾刃   │─────│   通用中心区   │─────│ 鱼骨大剑  │
  │(范围流·左)│     │  (能力升级)   │     │(爆发流·右)│
  └──────────┘     └───────┬───────┘     └──────────┘
                           │
                    ┌──────┴──────┐
                    │ 电磁铃铛    │
                    │(控制流·下)  │
                    └─────────────┘
```

**总节点数：65**（4武器分支 × 12 + 通用区15 + 探索独占2）

**武器分支结构（每条12节点/5档，含1对T3互斥分叉，每条路径购10节点）**：

| 档位 | 名称 | 节点数 | 单节点费用 | 前置条件 |
|:---:|------|:---:|:---:|------|
| **T1·磨爪** | 基础强化 | 2 | 1 | 无 |
| **T2·砺刃** | 核心分化 | 3 | 2 | ≥1个T1 |
| **T3·锋芒** | 流派深化（**分叉**） | 2+2互斥 | 3 | ≥1个T2 |
| **T4·爪印** | 精通特化 | 2 | 3 | ≥1个T3 |
| **T5·极意** | 终极猎杀 | 1 | 5 | 该分支T4全部 |
| **每分支总节点** | | **12** | | |
| **每分支路径费用** | | **10可购** | **25** | |

**T3分叉机制**：每个武器分支在T3层设**2条互斥路径**（路径A和路径B，各2个节点）。玩家选择一条路径后，另一条路径的2个节点自动锁定为不可购买。这代表流派深化的方向选择——例如猫爪分支可能分为「反击深化」(路径A)和「连招深化」(路径B)。选择定义了该武器在你手中的战斗性格。

**前置条件细节**：
- T4要求"≥1个T3"——两条T4路径均可从任一T3路径到达，但T4节点在主题上延续对应T3路径的设计方向
- T5要求"该分支T4全部"——仍需要购买2个T4节点

**通用中心区（15节点，5档）+ 2个探索独占节点**：

| 档位 | 名称 | 节点数 | 单节点费用 |
|:---:|------|:---:|:---:|
| T1 | 猎手本能 | 3 | 1 |
| T2 | 废土生存术 | 3 | 2 |
| T3 | 猫族秘传 | 3 | 3 |
| T4 | 九命之力 | 3 | 3 |
| T5 | 猫魂觉醒 | 3 | 5 |
| **常规合计** | | **15** | **42** |
| **探索独占** | 废土秘技 | **2** | **0**（不消耗技能点） |

**探索独占节点**：发现特定磨爪石祭坛时直接解锁（不消耗技能点），只有探索者才能获得。这两个节点提供独特的修改技能——

| 节点 | 名称 | 效果 | 参数 |
|------|------|------|------|
| 探索-1 | **猫影步** | 冲刺留下残影，短暂后爆炸 | 残影持续0.8秒，爆炸伤害=攻击力×30%，爆炸半径48px，冷却3秒 |
| 探索-2 | **废土直觉** | 进入新区域时短暂显示隐藏通道方向 | 显示持续2秒，以金色箭头指向最近隐藏通道，无冷却（每次进入新区域触发） |

这让探索改变了技能树的**结构**而非仅加速解锁——探索者获得了非探索者永远没有的战斗选项。

**总节点数：65**（4武器×12 + 通用15 + 探索独占2）。**可购买节点54个**（猫魂觉醒3选1互斥仅1可购，T3分叉每分支4个互斥节点仅2可购），满解费用**132点**（含1个猫魂）。

**满解费用分解**：4武器分支×25 + 通用T1-T4(27) + 猫魂觉醒(5) + 探索独占(0) = 100+27+5+0 = **132**

**Build空间验证**：65点 vs 132满解费 = **49.2%成本覆盖**。典型Build示例：
- **猫魂战士Build**：满解1条武器分支(25) + 通用区T1-T4(27) + 猫魂觉醒1个(5) + 第2条分支T1-T2(8) = 65点，余0
- **通用大师Build**：通用区全部含猫魂(32) + 1条武器满解(25) + 第2条分支T1-T2(8) = 65点，余0
- **均衡双武Build**：1条武器满解(25) + 通用区T1-T3(18) + 第2条武器T1-T3(16) + 猫魂觉醒(5) = 64点，余1

**设计意图**：65点预算让玩家可以完成一条武器深度(25)+通用能力(27)=52点，余13点足以探索第二条武器的T1-T3(16)或猫魂觉醒(5)+第二条T1-T2(8)。但无法满解两条武器分支(25×2+27=77>65)。这迫使玩家在"武器深度"和"多武器广度"之间做出有意义的Build决策。每条武器分支的T3分叉进一步增加了分支内选择——即使同一武器，不同玩家的Build也不同。

**节点类型比例约束**（确保"技巧优先"）：
- T1层：大部分被动，但通用区含1个修改型节点（废土韧体→受击无敌延长），确保入门体验不全是纯数值
- T2-T3层：50%主动/修改 + 50%被动（核心分化层，行为改变与数值并行）
- T4-T5层：80%主动/修改 + 20%被动（精通层，以行为改变为主）
- 总体目标：主动+修改节点 ≥ 35%（T3分叉结构下，部分节点因互斥不可购买，总可购节点54个）

**节点类型分类表**（基于可购买节点统计）：

| 层级 | 可购节点数 | 主动/修改 | 被动 | 比例 |
|------|:---:|:---:|:---:|:---:|
| 武器T1（8节点，含4修改型T1-A）| 8 | 4 | 4 | 50% |
| 武器T2-T3（每路径5/共20可购）| 20 | 10 | 10 | 50% |
| 武器T4（8节点）| 8 | 6 | 2 | 75% |
| 武器T5（4终极）| 4 | 4 | 0 | 100% |
| 通用T1（3节点，含1修改型）| 3 | 1 | 2 | 33% |
| 通用T2-T3（6节点）| 6 | 3 | 3 | 50% |
| 通用T4（3节点）| 3 | 2 | 1 | 67% |
| 通用T5（3猫魂，互斥选1，修改型）| 1可购 | 1 | 0 | 100% |
| 探索独占（2节点，免费）| 2 | 2 | 0 | 100% |
| **总计** | **54可购** | **33** | **22** | **61.1%** |

**说明**：T3分叉结构引入了每分支2对互斥节点（8个T3总节点中仅4个可购，每路径2个），总可购节点54个。主动/修改比例61.1%超过50%目标。武器T1层包含修改型节点（每武器1个T1-A），确保首次投资即改变战斗行为。猫魂觉醒归类为修改型（改变闪避/弹反/连招的行为模式）。

**设计约束**：每个武器分支的**T1层**和T2-T3层必须包含至少1个**修改技能**（改变已有招式行为的节点），确保玩家从首次投资起就能感受到"我的打法变了"而非"我的数字大了"。

**武器T1-A修改型节点定义**（每武器1个修改型+1个被动型）：

| 武器 | T1-A（修改型） | 效果 | T1-B（被动型） |
|------|---------------|------|---------------|
| **猫爪** | 疾步连爪 | 轻攻击第2击附带前冲位移(+8px) | 猫爪攻击力+5% |
| **长尾刃** | 延伸横扫 | 轻攻击第1击范围+0.3格 | 长尾刃攻击力+5% |
| **鱼骨大剑** | 重击震荡 | 重攻击命中附带微击退(8px) | 鱼骨攻击力+8% |
| **电磁铃铛** | 脉冲触击 | 轻攻击第1击命中附带短暂减速(0.5秒/15%) | 铃铛攻击力+5% |

**设计意图**：T1-A节点改变武器基础攻击行为而非数值——选择T1-A的玩家从第一点技能投资就感受到"这把武器在我手中不一样了"。T1-A和T1-B均只需1SP，玩家可以按偏好选择行为修改或数值加成。

#### 规则2：技能节点类型

| 类型 | 图标 | 颜色 | 作用 |
|------|------|------|------|

#### 规则4：猫气系统

**猫气系统的完整定义（获取、消耗、状态）由猫科战斗系统（feline-combat.md 规则7）管理。** 猫气是战斗资源，由战斗行为产生并由战斗技能消耗。

**技能树与猫气的交互**仅限于：
- **极意技门控**：T5节点购买后解锁该武器的极意技（消耗80猫气，详见feline-combat.md极意技消耗表）
- **Modifier接口**：技能树modifier可修改猫气获取率（当前65个节点中无此类节点，预留接口）

> 参见：feline-combat.md 规则7 — 猫气获取表、特殊招式消耗表、极意技消耗表、脱战清零规则。

#### 规则5：武器熟练度

**不采用独立熟练度系统。** 武器特化通过技能树投资深度自然实现——往某分支投入越多节点，该武器越强。这是Build决策，不是grind。

| 弹反 | 鹰眼 | T2 | 被动 | 暴击窗口+1帧 |
| 弹反 | 铁壁弹反 | T3 | 修改 | 窗口+3帧 |
| HP | 猎手耐力 | T2 | 被动 | +15（累计+25） |
| 生存 | 紧急回避 | T3 | 主动 | HP<20%免疫致命伤害，90秒CD |

**设计说明**：通用T1"废土韧体"被归类为**修改型**节点（非纯被动数值），它改变了受击后的行为模式（延长无敌帧），确保玩家在通用区的首次投资就能感受到"我的打法变了"而非仅"数字变大了"。

#### T5通用节点：猫魂觉醒（3个终极节点）

通用中心区T5档的3个节点为**猫魂形态**——每个节点赋予一种战斗风格转变，代表猫族远古猎魂的力量。每节点5点，总计15点。

| 节点 | 名称 | 效果 | 设计意图 |
|------|------|------|---------|
| T5-1 | **猎之魂** | 完整连招（3击全中）后移速+40%持续3秒 | 奖励进攻节奏——连续输出获得机动性 |
| T5-2 | **影之魂** | 闪避留下残影（持续0.5秒），残影爆炸造成50%伤害 | 奖励精准闪避——防御动作变为攻击机会 |
| T5-3 | **铁之魂** | 弹反成功后获得护盾（吸收10点伤害，持续5秒） | 奖励高风险防御——弹反从纯反击变为生存保障 |

**设计理念**：3个T5节点分别对应进攻（猎）、闪避（影）、弹反（铁）三种核心战斗行为。每个都将**已有的技巧操作**转化为**新的行为维度**——不是数值变大，而是操作有了新意义。

**互斥规则**：3个猫魂形态**互斥**——解锁其中1个后，另外2个自动锁定为不可购买状态。玩家必须在猎/影/铁之间做出选择，这个选择定义了猫武士的战斗身份。选择猎之魂的猫是「进攻猎手」，选择影之魂的是「暗影刺客」，选择铁之魂的是「铁壁守护者」。洗点后可重新选择。

#### 规则7：Modifier Provider接口

技能树通过统一接口向战斗系统提供加成：

```
skill_tree.register_modifier(
    skill_id,           # 技能ID
    modifier_type,      # "PASSIVE" | "MODIFIER" | "ULTIMATE"
    target_action_id,   # 作用目标招式
    stat_key,           # 修改的属性
    operation,          # "ADD" | "MULTIPLY" | "OVERRIDE"
    value,              # 修改值
    condition           # 可选触发条件
)

skill_tree.get_modifiers(action_id) → Array[Modifier]
skill_tree.get_stat_bonus(stat_key) → float
```

应用顺序：武器基础 → PASSIVE（相加）→ MODIFIER（依次）→ 护符 → 状态效果 → 最终clamp

### States and Transitions

**技能节点状态**：

| 状态 | 视觉 | 可交互 | 说明 |
|------|------|:---:|------|
| **LOCKED** | 深灰+锁链 | 否 | 前置条件不满足 |
| **AVAILABLE** | 半透明+脉动光晕 | 是 | 前置满足，可投入技能点 |
| **UNLOCKED** | 全亮+类型颜色 | 否 | 效果已生效 |

**状态转换**：LOCKED → AVAILABLE（前置满足）→ UNLOCKED（投入技能点）

**节点解锁流程**：
1. 玩家选择节点 → 2. 检查前置+技能点 → 3. 确认投入 → 4. 播放解锁动画（0.8秒）→ 5. 效果立即生效 → 6. modifier注册到战斗系统 → 7. 存档 → 8. HUD通知

**猫气状态**（详见 feline-combat.md 规则7）：

| 状态 | 条件 |
|------|------|
| 空（0） | 战斗开始/脱战后 |
| 充能中 | 攻击/闪避/弹反积累 |
| 满（100） | 可释放任意特殊招式 |

## Formulas

### F1: 技能点总预算

`total_sp_available = boss_sp + elite_sp + explore_sp + quest_sp`

| 变量 | 符号 | 类型 | 范围 | 描述 |
|------|------|------|------|------|
| Boss击败奖励 | `boss_sp` | int | MVP:5, Full:20 | 每Boss=5点×MVP1Boss/Full4Boss |
| 精英敌人奖励 | `elite_sp` | int | MVP:2, Full:16 | 每精英=2点×MVP3精英/Full8精英 |
| 探索发现奖励 | `explore_sp` | int | MVP:3, Full:21 | 每祭坛=3点×MVP3祭坛/Full7祭坛 |
| 任务奖励 | `quest_sp` | int | MVP:2, Full:8 | 每任务=2点×MVP1任务/Full4任务 |
| **输出** | `total_sp_available` | int | MVP:22, Full:65 | 全游戏可获取技能点总数 |

**输出范围**：MVP=22点，Full=65点。

**示例**：Full = 20(Boss) + 16(精英) + 21(探索) + 8(任务) = **65点**

**Build空间验证**：65点 vs 132满解费 = **49.2%成本覆盖**。典型Build示例：
- **猫魂战士Build**：满解1条武器分支(25) + 通用区T1-T4(27) + 猫魂觉醒1个(5) + 第2条分支T1-T2(8) = 65点，余0
- **通用大师Build**：通用区全部含猫魂(32) + 1条武器满解(25) + 第2条分支T1-T2(8) = 65点，余0
- **均衡双武Build**：1条武器满解(25) + 通用区T1-T3(18) + 第2条武器T1-T3(16) + 猫魂觉醒(5) = 64点，余1
- **广猎多武Build**：通用区含猫魂(32) + 1条武器T1-T3(16) + 第2条武器T1-T2(8) = 56点，余9可推第3条武器T1-T2(8)=64点，余1

**设计意图**：65点预算让玩家可以完成一条武器深度(25)+通用能力(27)=52点，余13点足以探索第二条武器的T1-T3(16)或猫魂觉醒(5)+第二条T1-T2(8)。但无法满解两条武器分支(25×2+27=77>65)。每条武器分支的T3分叉进一步增加了Build多样性——同一武器的不同路径选择创造不同的战斗风格。这迫使玩家在"武器深度"、"多武器广度"和"猫魂身份"之间做出有意义的Build决策。

### F2: 技能节点成本

`node_cost = tier_cost[node.tier]`

| 档位 | 成本 |
|:---:|:---:|
| T1 | 1 |
| T2 | 2 |
| T3 | 3 |
| T4 | 3 |
| T5 | 5 |

**输出范围**：1（T1基础节点）到 5（T5终极节点）。

**单武器分支路径费用**：2×1 + 3×2 + 2×3(T3选择路径) + 2×3 + 1×5 = **25点**（每分支12节点中购买10个，T3互斥跳过2个）

### F3: 洗点成本

`respec_cost = prior_respec_count == 0 ? 0 : min(30 + (prior_respec_count - 1) × 10, 100)`

| 变量 | 符号 | 类型 | 范围 | 描述 |
|------|------|------|------|------|
| 已完成洗点次数 | `prior_respec_count` | int | 0-∞ | 本次洗点**之前**已完成的洗点次数（≥0） |
| **输出** | `respec_cost` | int | 0-100 | 本次洗点需支付的齿轮币 |

**输出范围**：0（首次免费）到 100齿轮币封顶。

**示例**：第1次=0（免费），第2次=30，第3次=40，第4次=50，第9次=100（封顶）

### F4: 被动技能加成

`passive_bonus = node.passive_value`（查表值）

| 被动类型 | 单节点范围 | 技能树最大累计 |
|----------|:---:|:---:|
| 攻击力加成 | +5%~+10% | +25% |
| HP加成 | +5~+15 | +25 |
| 暴击窗口扩大 | +1~+2帧 | +4帧 |
| 连招倍率加成 | +5%~+10% | +20% |
| 移速加成 | +5%~+8% | +15% |

### F5: 修正技能效果

`modifier_effect = max(0, base_value × (1 + modifier_value))`（比例型，含下界保护）
`modifier_effect = base_value + modifier_flat`（固定值型）

**下界保护**：`max(0, ...)` 防止多个负面modifier叠加（如debuff -30% + debuff -40% = -70%）时 `base × (1 + (-0.7))` 产出负值或零以下结果。比例型modifier的最终效果永不为负。

| 修正类型 | 修正值范围 | 作用方式 |
|----------|:---:|------|
| 冲刺距离 | +25%~+50% | 比例型 |
| 弹反窗口 | +2~+4帧 | 固定值型 |
| 闪避i-frame | +2~+4帧 | 固定值型 |
| 减速效果 | +10%~+20% | 比例型 |
| 连招超时窗口 | +50~+100ms | 固定值型 |
| 特殊招式冷却 | -15%~-30% | 比例型（减少） |

**示例**：冲刺距离96px + 技能+25% → 96 × 1.25 = **120px**

**Modifier叠加语义**：当多个modifier作用于同一属性时：
1. 所有 `ADD` 类型 modifier 的 value **先求和**（加算）
2. 然后作为一次乘算应用于 base_value
3. `MULTIPLY` 类型 modifier 在 ADD 加算结果之后**依次乘算**（每个 MULTIPLY 乘以当前累计值）
4. `OVERRIDE` 类型直接替换最终值，无视其他 modifier

**MULTIPLY 叠加示例**：ADD合计+20%，MULTIPLY A=×1.5，MULTIPLY B=×1.2 → 结果 = base × 1.20 × 1.5 × 1.2 = base × 2.16

**OVERRIDE 冲突解决**：当多个 OVERRIDE 同时作用于同一属性时，按以下优先级：技能树 > 护符 > 状态效果。同优先级内，后注册的覆盖先注册的。

**示例**：modifier A=+20%, modifier B=+15%（均为ADD）→ 总修正 = +35%（不是 ×1.2×1.15=×1.38）

### F6: 极意技伤害

**前提条件**：该武器的T5节点已购买。未购买T5时，`ultimate_multiplier` = 0（极意技不可用）。

`ultimate_base = ultimate_multiplier × (effective_weapon_base + attack_power × 0.3)`
`ultimate_final = clamp(floor(ultimate_base × skill_modifier × reduction_factor), 1, 999)`

| 变量 | 符号 | 类型 | 范围 | 描述 |
|------|------|------|------|------|
| 极意技倍率 | `ultimate_multiplier` | float | 3.0-5.0 | 按武器不同（见下表） |
| 有效武器基础伤害 | `effective_weapon_base` | int | 8-46 | 当F9生效时 = `weapon_base × (1 + skill_weapon_bonus)`；当F9无加成时 = 原始 `weapon_base` |
| 攻击力 | `attack_power` | int | 0-50 | 角色攻击力属性 |
| 技能修正系数 | `skill_modifier` | float | 1.0-1.25 | `1 + skill_bonus_total["damage"]`（F7聚合输出，上限0.25） |
| 防御减伤系数 | `reduction_factor` | float | 0.0-1.0 | `clamp(60 / (defense + 60), 0.0, 1.0)`（damage-calculation F3输出，防御性clamp） |

**不变量声明**：`reduction_factor` ∈ [0, 1.0]。防御性clamp已内置于公式：`reduction_factor = clamp(60 / (defense + 60), 0.0, 1.0)`。此clamp防止以下边缘情况：defense为负值时reduction_factor > 1.0（伤害放大）、defense = -60时除零崩溃。

| 武器 | 极意技 | multiplier | 冷却 |
|------|--------|:---:|:---:|
| 猫爪 | 九命乱舞 | 3.5 | 60秒 |
| 长尾刃 | 银弧断空 | 4.0 | 75秒 |
| 鱼骨大剑 | 鱼骨天崩 | 5.0 | 90秒 |
| 电磁铃铛 | 电磁风暴 | 3.0 | 120秒 |

**示例**：满级鱼骨(effective_weapon_base=40, attack_power=30, skill_modifier=1.0) → ultimate_base = 5.0 × (40+30×0.3) = 5.0 × 49 = **245** → vs def50(reduction=clamp(60/(50+60), 0, 1.0)≈0.5455) → final = floor(245 × 1.0 × 0.5455) = floor(133.6) = **133**

**F9交互说明**：当武器分支被动提升weapon_base（F9的`skill_weapon_bonus`）时，`effective_weapon_base`使用F9的输出值`skill_weapon_base`。例如：鱼骨weapon_base=40 + skill_weapon_bonus=+15% → effective_weapon_base = 40 × 1.15 = 46。

### F7: 技能加成聚合

`skill_bonus_total[stat] = min(skill_cap[stat], Σ unlocked_skills[stat].bonus)`

**轨道分离**：`skill_weapon_bonus`（F9中修改weapon_base的武器分支被动，最高+15%）属于**基础修正轨道**，不计入F7 skill_cap。F7 cap仅适用于通用百分比加成节点。两条轨道独立受控，最终在F8统一cap中汇合。

| 属性类型 | skill_cap |
|----------|:---:|
| 伤害加成 | 0.25 |
| HP加成 | +25(flat) |
| 暴击窗口 | +4帧 |
| 连招倍率 | 0.20 |
| 移速 | 0.15 |
| 冷却缩减 | 0.30 |
| 弹反窗口 | +4帧 |

### F8: 技能与护符交互

`combined_bonus[stat] = min(0.75, 1 - (1 - skill_bonus_total[stat]) × (1 - clamped_charm_bonus[stat]))`
`final_stat = base_stat × (1 + combined_bonus)`（比例型）

**输入防御**：`clamped_charm_bonus = clamp(charm_bonus, 0.0, charm_cap)`。charm_bonus在进入乘法递减公式前必须先clamp到[0, charm_cap(0.50)]，防止charm_bonus > 1.0时公式反转（`(1 - charm_bonus)`变为负数）或debuff场景下产生非预期结果。

技能加成和护符加成采用**乘法递减叠加**——两者永远互补，不会互相归零。软上限0.75确保在设计范围内的数值（skill_cap=0.25, charm_cap=0.50）不会触发clamp截断。

**设计理由**：加法叠加+硬上限会导致"charm达到cap时技能贡献归零"的perverse incentive。乘法递减+软上限0.75确保：skill=0.25 + charm=0.50 → combined=1-(0.75×0.50)=0.625（两者都有贡献，未触顶）。仅当charm>0.50且skill>0.25的极端情况下才触顶clamp。

**验证（设计范围内不触顶）**：
- skill=0.25(cap), charm=0.50(cap) → 1-(0.75×0.50)=0.625 < 0.75 ✓ 两者均有贡献
- skill=0.10, charm=0.30 → 1-(0.90×0.70)=0.37 < 0.75 ✓
- skill=0.25, charm=0.75(超出设计范围) → 1-(0.75×0.25)=0.8125 → clamp到0.75

**执行顺序与所有权**：
1. 护符系统计算 `charm_bonus[stat]`（同类不叠加，cap 0.50）
2. 技能树计算 `skill_bonus_total[stat]`（F7聚合）
3. **技能树负责执行统一上限**：按乘法递减公式计算combined_bonus，再clamp到0.75
4. `final_stat` 由消费方（伤害计算/生命系统等）按此公式计算

护符系统只需将 `charm_bonus` 作为输入传入本公式。最终cap由技能树统一执行。

### F9: 技能与武器升级交互

`skill_weapon_base = weapon_base[level] × (1 + skill_weapon_bonus)`
`skill_base_damage = skill_weapon_base + floor(attack_power × 0.2)`

技能对weapon_base的加成是**乘法**——武器等级越高，技能加成的绝对收益越大。

**轨道说明**：`skill_weapon_bonus` 是**基础修正**——它在伤害流水线的第0步替换weapon_base，随后所有百分比加成（F7通用节点、护符等）基于提升后的base计算。这与F7的通用伤害cap（+25%）是独立轨道，两者互不干扰。文档注明：武器分支被动提升的是"底数"，所有百分比加成都从这个更高的底数起算。

**与伤害计算系统的衔接**：`skill_base_damage` 替代 damage-calculation F1 中的 `base_damage` 进入伤害流水线。当技能树无武器基础修正时（skill_weapon_bonus=0），`skill_base_damage` = 原始 `base_damage`。

**跨系统反向依赖**：damage-calculation GDD需在F1中注明："当skill-tree F9生效时，weapon_base被skill_weapon_base替换后再进入本公式。"

### F10: 冷却修正

`effective_cooldown = max(cooldown_floor, base_cooldown × (1 - min(skill_cd_reduction, skill_cd_reduction_cap)))`

**注意**：`skill_cd_reduction` 必须先clamp到 [0, skill_cd_reduction_cap(0.30)] 再进入公式，防止超cap导致零冷却。

| 能力 | base_cd | cd_floor | 最大缩减后 |
|------|:---:|:---:|:---:|
| 闪避 | 0.5s | 0.3s | 0.35s |
| 冲刺 | 1.0s | 0.5s | 0.7s |
| 弹反 | 0.3s | 0.2s | 0.21s |
| 极意技(最短) | 60s | 30s | 42s |

## Edge Cases

- **If 技能点不足以解锁节点**: 节点保持AVAILABLE状态，显示"需要更多磨爪经验"，不消耗任何资源
- **If 前置条件未满足时点击节点**: 节点显示LOCKED+灰色，显示所需前置节点名称
- **If 洗点后技能点返还**: 所有已解锁节点重置为LOCKED/AVAILABLE，技能点全额返还（首次免费，后续扣齿轮币）
- **If 洗点时齿轮币不足**: 不允许洗点，显示"齿轮币不足"
- **If 猫气已满时继续攻击**: 猫气保持在100，不溢出，不额外奖励
- **If 猫气不足但冷却已完成时按特殊键**: 显示"猫气不足"提示，不消耗冷却
- **If 冷却未完成但猫气已满时按特殊键**: 显示冷却UI，不消耗猫气
- **If 同时满足多个前置条件的节点**: 任一满足前置路径即可解锁，不要求特定路线
- **If 切换武器时猫气**: 猫气是全局资源，不随武器切换清零
- **If Boss战中尝试洗点**: 不允许，只有安全区域可洗点
- **If 存档加载时技能ID不存在**: 忽略该节点+输出WARNING，其余正常恢复
- **If 技能树数据文件验证失败**: DataManager保留旧缓存（热重载）或使用默认值（首次加载），不崩溃
- **If 两个修改技能修改同一属性**: 两个modifier依次应用（按注册顺序），最终受F7 skill_cap约束
- **If 技能加成+护符加成超过0.75**: clamp到0.75，UI显示溢出提示（灰色+溢出量）
- **If 猫魂觉醒已解锁1个形态**: 另外2个猫魂节点自动锁定（显示"已选择其他猫魂"），不可购买
- **If 洗点后重新选择猫魂**: 所有猫魂节点重置为AVAILABLE，玩家可重新选择
- **If 极意技未解锁(T5未购买)时按特殊键**: 无反应（不消耗猫气，不进入冷却），UI显示"极意未悟"
- **If 两个OVERRIDE modifier冲突**: 按优先级处理——技能树 > 护符 > 状态效果；同优先级后注册覆盖先注册
- **If 选择T3路径A后查看路径B节点**: 路径B的2个节点显示锁定状态+"已选择另一流派"，不可购买
- **If 洗点后重新选择T3路径**: 所有T3节点重置为AVAILABLE，玩家可重新选择流派方向
- **If 受击后废土韧体效果触发**: 受击无敌帧延长0.1秒，在无敌帧期间不受伤害且不进入受击硬直

## Acceptance Criteria

- **GIVEN** 玩家首次打开技能树，**WHEN** 拥有0技能点，**THEN** T1节点显示为AVAILABLE（可购买），T2+节点显示LOCKED
- **GIVEN** 玩家拥有1技能点，**WHEN** 点击T1节点并确认，**THEN** 节点变为UNLOCKED，效果立即生效，技能点归零
- **GIVEN** 玩家已解锁某分支T1中1个节点，**WHEN** 拥有2技能点，**THEN** T2节点变为AVAILABLE
- **GIVEN** 玩家已解锁某分支全部T4节点，**WHEN** 拥有5技能点，**THEN** T5终极节点变为AVAILABLE
- **GIVEN** 猫气为0，**WHEN** 普通攻击命中1次，**THEN** 猫气变为5
- **GIVEN** 猫气≥30且疾风连爪冷却完成，**WHEN** 猫爪装备中按特殊键，**THEN** 执行疾风连爪，猫气-30，冷却开始
- **GIVEN** 猫气<30，**WHEN** 按特殊键，**THEN** 显示"猫气不足"提示，不消耗冷却
- **GIVEN** 冷却未完成但猫气已满，**WHEN** 按特殊键，**THEN** 显示冷却UI，不消耗猫气
- **GIVEN** 玩家首次洗点，**WHEN** 在据点导师NPC选择洗点，**THEN** 所有节点重置，技能点全额返还，齿轮币不变
- **GIVEN** 玩家第2次洗点，**WHEN** 齿轮币≥30，**THEN** 洗点成功，齿轮币-30
- **GIVEN** 玩家第2次洗点，**WHEN** 齿轮币<30，**THEN** 显示"齿轮币不足"，洗点失败
- **GIVEN** 猫气已满，**WHEN** 继续攻击命中，**THEN** 猫气保持100，不溢出
- **GIVEN** 玩家切换武器，**WHEN** 切换完成，**THEN** 猫气不清零（全局资源）
- **GIVEN** 角色拥有F7聚合后的skill_bonus_total[伤害]=0.25(cap值)且charm_bonus[伤害]=0.25，**WHEN** 计算combined_bonus，**THEN** 结果=1-(1-0.25)×(1-0.25)=1-0.5625=0.4375(43.75%±0.01%)，不超过0.75软上限
- **GIVEN** 角色拥有skill_bonus_total[伤害]=0.25(cap值)且charm_bonus[伤害]=0.50(cap值)，**WHEN** 计算combined_bonus，**THEN** 结果=1-(0.75×0.50)=0.625(62.5%)，不超过0.75软上限——证明在设计cap范围内技能贡献不会被抹零
- **GIVEN** Boss被击败，**WHEN** 击败动画完成，**THEN** 技能点余额立即+5，HUD顶部弹出"+5 技能点"通知持续3秒后自动消失
- **GIVEN** 存档加载，**WHEN** 某技能ID不存在于当前版本，**THEN** 忽略该节点+输出WARN级别日志，其余正常
- **GIVEN** 满级鱼骨大剑(weapon_base=40, attack_power=30, T5已解锁)，**WHEN** 释放鱼骨天崩(ultimate_multiplier=5.0, skill_modifier=1.0, 猫气≥80)命中def50敌人(reduction=60/(50+60)≈0.5455)，**THEN** 最终伤害=floor(5.0×(40+30×0.3)×1.0×0.5455)=floor(245×0.5455)=floor(133.6)=**133**
- **GIVEN** 两个ADD modifier(+20%和+15%)作用于同一属性，**WHEN** 计算最终修正，**THEN** ADD先求和为+35%，应用为base_value×1.35（不是×1.2×1.15=×1.38）
- **GIVEN** 角色已达到F7伤害加成上限(+25%)，**WHEN** 尝试解锁新的+伤害节点，**THEN** 节点仍可购买（提供其他效果），但额外伤害加成被cap截断，UI显示cap溢出提示
- **GIVEN** 已解锁猫爪专属技能"疾风连爪"，**WHEN** 切换到非猫爪武器并按特殊键，**THEN** 执行当前武器的特殊攻击（非疾风连爪），猫气消耗按当前武器技能计算
- **GIVEN** 冷却缩减效果累计达到40%（超过cap 30%），**WHEN** 计算技能实际冷却时间，**THEN** 缩减先clamp到30%，冷却不低于cooldown_floor，不出现零冷却
- **GIVEN** 玩家在探索中发现磨爪石祭坛，**WHEN** 返回技能树界面，**THEN** 对应探索节点显示为UNLOCKED（0技能点消耗），节点效果生效，节点有金色边框视觉区分
- **GIVEN** 已解锁猎之魂（猫魂觉醒T5），**WHEN** 查看影之魂和铁之魂节点，**THEN** 两个节点显示"已选择其他猫魂"锁定状态，不可购买
- **GIVEN** 猫爪分支T5未购买，**WHEN** 按特殊键+猫气≥80，**THEN** 不执行九命乱舞（极意技未解锁），无猫气消耗，无冷却触发
- **GIVEN** 某武器分支T3层尚未选择路径，**WHEN** 玩家购买T3-A路径的第1个节点并确认，**THEN** T3-A的另一个节点变为AVAILABLE，T3-B的2个节点自动锁定并显示"已选择另一流派"
- **GIVEN** 已选择T3-A路径，**WHEN** 查看该分支的T4层，**THEN** 两个T4节点均显示AVAILABLE（T4前置为"≥1个T3"，已满足）
- **GIVEN** 玩家已购买通用T1"废土韧体"（修改型），**WHEN** 角色受到敌人攻击命中，**THEN** 受击无敌帧延长0.1秒，期间角色不受伤害且不进入受击硬直
- **GIVEN** 洗点后T3路径重置，**WHEN** 重新选择T3路径，**THEN** 所有T3节点（含之前锁定的路径B）均恢复AVAILABLE，可重新选择
- **GIVEN** 猫爪分支已解锁"疾步连爪"(T1-A修改型, 轻攻击第2击附带前冲位移+8px)，**WHEN** 调用`get_modifiers("light_attack_2")`，**THEN** 返回Array包含{stat_key: "dash_distance", operation: "ADD", value: 8}的Modifier对象
- **GIVEN** 猫爪T1-B("猫爪攻击力+5%")已解锁且猫爪T2-1("连招倍率+8%")已解锁，**WHEN** 调用`get_stat_bonus("damage")`，**THEN** 返回0.05；调用`get_stat_bonus("combo_multiplier")`，**THEN** 返回0.08；调用`has_skill("cat_claw_t1b")`，**THEN** 返回true
- **GIVEN** 鱼骨大剑分支被动已解锁(skill_weapon_bonus=+15%)且weapon_base=40、attack_power=30，**WHEN** 计算F9 skill_base_damage，**THEN** effective_weapon_base=40×(1+0.15)=46，skill_base_damage=46+floor(30×0.2)=46+6=**52**（非原始base_damage=40+6=46）
