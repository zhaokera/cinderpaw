## Context

**GDD**: `design/gdd/combat-presentation.md`
**Requirements**: `TR-combatfx-003`, `TR-combatfx-007`
**ADR Governing Implementation**: ADR-0002: Signal communication

CombatPresentation now has textured hit sparks, parry sparks, claw trails,
dodge afterimages, kill debris, and Boss phase debris. The GDD requires the
particle system to support the planned particle families while never allowing
more than 200 simultaneous particles. It also defines a performance budget for
combat presentation work. This story adds deterministic guardrails before more
VFX families are layered onto the main scene.

## Acceptance Criteria

- [x] `CombatPresentation` exposes a 200-particle cap through
  `get_particle_cap()` and reports active particle count through
  `get_active_particle_count()`.
- [x] The active particle count includes Sprite2D particle effects generated by
  hit sparks, kill debris, parry sparks, cat-claw trails, dodge afterimages, and
  Boss phase debris.
- [x] Damage-number labels, full-screen flash overlays, and Boss phase overlays
  do not count toward the 200 Sprite2D particle cap.
- [x] When spawning new particles would exceed 200 active particles, the oldest
  particle effects are evicted first and their nodes are queued for cleanup.
- [x] Existing per-event counts remain unchanged when the active count is under
  the cap.
- [x] `CombatPresentation.capture_performance_budget_sample(sample_frames)`
  returns measured per-frame sample costs and the GDD budgets:
  particles `<2ms`, hitstop/shake `<0.1ms`, total presentation `<3ms`.
- [x] Performance sampling is diagnostic only: it must not advance lifetimes,
  change hitstop/shake state, or remove particles.
- [x] Godot MCP runs `res://scenes/main.tscn`, stress-spawns particles, verifies
  active particles are capped at 200, checks clean logs, and captures a
  nonblank screenshot.

## Implementation Notes

- Stay Presentation-only. Do not make CombatPresentation call Core or Feature
  systems.
- Count only transient Sprite2D particle effects in the particle budget:
  `_sparks`, `_debris`, `_parry_sparks`, `_trails`, `_afterimages`, and
  `_boss_phase_debris`.
- Keep non-particle presentation elements outside the cap: damage-number
  labels, `TextureRect` flash overlays, and Boss phase screen overlays.
- Preserve all existing GDD counts, colors, lifetimes, hitstop values, and
  screen-shake values when the cap is not exceeded.
- Performance sampling should use stable averaged local timing and broad GDD
  thresholds; exact screenshot pixel colors or single-frame wall-clock spikes
  are not acceptance criteria.

## Out of Scope

- Replacing Sprite2D particles with `GPUParticles2D` or pooling.
- Implementing the missing long-tail, fish-bone, or electro-bell VFX families.
- Adding new generated art assets.
- Changing combat formulas, damage-number tiers, HUD settings, or audio.
- Mobile dynamic VFX quality scaling.

## QA Test Cases

- **AC-1**: Particle cap API
  - Given: a new `CombatPresentation`
  - When: tests query `get_particle_cap()` and `get_active_particle_count()`
  - Then: cap is `200` and active count starts at `0`
  - Edge cases: no particles, mixed particle families

- **AC-2**: Oldest-first eviction
  - Given: a normal hit has spawned spark particles
  - When: repeated Boss phase transitions spawn more than 200 total particles
  - Then: active particle count is exactly `200`, original spark particles have
    been evicted first, and eviction count equals spawned particles minus cap
  - Edge cases: Boss overlays should remain outside the particle cap

- **AC-3**: Cap membership
  - Given: damage numbers, flash overlays, dodge afterimages, parry sparks, claw
    trails, hit sparks, and Boss debris are active
  - When: active particle count is queried
  - Then: count equals the sum of Sprite2D particle arrays only
  - Edge cases: damage labels and TextureRect overlays are not counted

- **AC-4**: Performance guardrail sample
  - Given: a capped stress scene with active combat particles
  - When: `capture_performance_budget_sample(120)` is called
  - Then: returned budget values match GDD thresholds and measured averages are
    within budget without mutating particle lifetime or hitstop/shake state
  - Edge cases: `sample_frames <= 0` clamps to one sample
